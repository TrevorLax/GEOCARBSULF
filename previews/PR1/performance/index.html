Performance

How fast the Julia port is, compared with the original R/Fortran code, is measured by the timing benchmark in benchmark/timing (plan: TIMING_BENCHMARK_PLAN.md; usage: benchmark/timing/README.md). It times every stage of the workflow in both implementations on the same machine, checks the results of every timed block, and writes a report with medians, interquartile ranges and 95 % bootstrap intervals for the speed-ups.

run_timing.bat --suite quick          (Windows)
julia --project=benchmark/timing benchmark/timing/run_timing.jl --suite quick

No numbers are given on this page yet: they depend on the machine, and the reference numbers will be taken from a standard run on the machine that ran the legacy comparison. When they are added, they will come with that run's env.toml (CPU, RAM, OS, Julia and R versions, BLAS, gfortran flags, power plan and antivirus state).

Instrumentation in the package

run_precalibration contains timing sections written with TimerOutputs.@timeit_debug. They compile to nothing unless switched on:

using GeocarbPrecalibration, TimerOutputs
TimerOutputs.enable_debug_timings(GeocarbPrecalibration)
run_precalibration(cfg; max_parallel = 1)
GeocarbPrecalibration.TIMER          # the accumulated sections
TimerOutputs.disable_debug_timings(GeocarbPrecalibration)

Use them with one thread only: the timer is shared between chunks.
