Porting notes

This page records how the R/Fortran code maps onto the Julia package and every decision that makes the two differ. Finding numbers (F-xx) refer to the review of the original code carried out before the port, and decision numbers (D-x) to the porting decisions taken from it (internal planning documents, not distributed). Each finding used in the code is described where it is cited.

Deliberate differences from the R/Fortran code

  • Literal precision (F-05). The compiled Fortran uses single-precision values of 0.01, 0.9, 0.2, 0.7, 0.6, 0.8, 1.2 and log(2.0). Version 1 reproduces them by default (fortran_single_literals = true), so this is not a difference unless you opt out. With false, every literal is Float64; on the 1000-sample legacy comparison that changes the pass/fail outcome of 101 runs and CO2 by up to 14 % in otherwise valid steps, so treat it as a model change, not a precision improvement.
  • Last-bit rounding of exp, log and ^. Julia's maths library and the C runtime gfortran links against round differently now and then. Valid steps agree to about 4e-9 relative; after a run's first failed step the legacy model keeps integrating from an invalid state (F-08) and the difference grows to about 1e-6. The tests therefore use rtol = 1e-8 before and 1e-4 after the first failure (see Testing).
  • NaN instead of exceptions. Powers and logarithms of negative numbers give NaN as in Fortran (nanpow, nanlog), never a DomainError.
  • gym_factor = 0 is well defined (the Fortran divides by it; F-09).
  • ΔT2x ramp is off unless dT2X_ramp = true. The R default supp_experiment_parameters = c(130, 80, 1, 1) silently switched it on (F-09).
  • Random numbers. Julia uses StableRNG streams per chunk, so individual samples differ from R's. Constants come from a Latin hypercube per chunk by default (D5).
  • Single chunk. n_sample ≤ n_per_chunk works (a stub in R, F-12).
  • Cretaceous stage 2. The forcing centres are the mean accepted series of stage 1, matched by name. In R, par_time_mean_cret.csv was written with row names and read back with read.csv, which adds an X column, so every forcing shifted by one column and Sr became 1, 2, …, 58 (F-27, found during the port). Please check whether the published stage-2 results were affected.
  • Seeds. lhs_sampling_cret.R overrode the driver seed with set.seed(2021) (F-18); in Julia the seed comes only from the configuration.
  • Analysis. The duplicated deltaT2Xglac row and quantiles of placeholder zeros (F-17) are not reproduced. Hindcasts reuse saved outputs. Numbers are written to numbers.toml instead of being printed.

Not ported (yet)

  • Reading the legacy .RData outputs (RData.jl could be added as a package extension).
  • Seven of the seventeen R figures (KDE panels of every parameter, sample-size convergence, the supplemental hindcast grid, Cretaceous panels). The numbers behind them are available from src/analysis.
  • The PR2011 and LENTON time-array files and the PR2011 prior file are not in the repository (F-14). The configuration accepts them once they are added to data/.
