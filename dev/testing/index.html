The legacy comparison runs the unmodified R code on 1000 samples and feeds exactly those samples to Julia, using the default fortran_single_literals = true. The regression golden test does the same on 100 of those samples stored in test/fixtures/fortran/, so it runs without R.

Tolerances

Both tests judge every run in two regions, split at the run's first failed step (the first Inf in the legacy CO2):

checkrequirement
Inf/NaN positionsidentical (the same steps fail)
% outboundidentical
values before the first failed stepabs(a − b) ≤ 1e-10 + 1e-8·max(abs(a), abs(b))
values at or after the first failed stepabs(a − b) ≤ 1e-10 + 1e-4·max(abs(a), abs(b))

Why two regions: Julia's exp, log and ^ and the C runtime used by gfortran occasionally round the last bit differently. Two builds of the same Fortran (the main and supplemental libraries) already differ by up to 8e-10 for that reason. In a valid step the model is well conditioned and the difference stays below about 4e-9. After a failed step the legacy code keeps integrating from an invalid state (finding F-08), the next steps are badly conditioned, and the same last-bit difference grows to about 1e-6. A real porting error is still caught: it changes valid steps far more than 1e-8, or moves a failure, or changes a % outbound.

The report (test/legacy_comparison/output/comparison_report.txt) lists the worst cells of each region with their run, age, step status, solver iterations and the age of the run's first failure. The tolerances are kept in test/tolerances.toml, which the golden-master test reads too; CI never overrides them, and a change to the file needs a CHANGELOG entry that says so. For experiments they can be overridden with --rtol-clean, --rtol-post and --atol. With CairoMakie installed, the run also draws figures of these differences into test/legacy_comparison/output/figures/ (see test/legacy_comparison/README.md).

The comparison also reports, for information only, how far Julia with fortran_single_literals = false is from the legacy output (pass/fail flips and relative differences).

Continuous integration

Before code reaches GitHub, the prek hooks in .pre-commit-config.yaml (see CONTRIBUTING.md) format it, and on every git push run the CHANGELOG/AI-usage check, the golden test and the full live comparison with the R/Fortran code.

GitHub Actions (.github/workflows/) runs on every push and pull request:

workflowcheck namewhat
CI.ymlCI resultPkg.test() on Linux, macOS and Windows × Julia 1.10 (LTS) and 1, plus 4 threads and the pre-release (allowed to fail); coverage to Codecov. Includes the regression golden test, so every platform is checked against the Fortran output
Legacy.ymlLegacy comparisonon a pinned toolchain (ubuntu-24.04, R 4.6.1, dated CRAN snapshot): builds the original Fortran with gfortran, runs the unmodified R code and run_comparison.jl, then regenerates the golden fixtures from that Fortran and runs the golden test on them; report in the job summary, all output as an artifact

Branch protection on main should require CI result, Legacy comparison, Documentation, Formatting, Metadata, Changelog and AI usage and Lint.

Retiring the comparison with the R/Fortran code

The live comparison is meant to be temporary. To drop it:

  1. delete .github/workflows/Legacy.yml, the legacy job in Weekly.yml and the legacy-comparison hook in .pre-commit-config.yaml;
  2. remove Legacy comparison from the required checks of main;
  3. keep test/regression, test/fixtures/fortran/ and test/tolerances.toml. They keep pinning the model to the original Fortran output on every platform, without R. legacy/ and test/legacy_comparison/ can stay so the comparison can still be run by hand.
